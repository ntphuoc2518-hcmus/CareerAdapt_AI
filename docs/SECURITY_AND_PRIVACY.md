# CareerAdapt security and privacy notes (Steps 12–18)

## Ownership and identity

- The `authenticated_user_id` passed to `src/data_access.py` must come from a verified server-side identity/token. Never trust `X-User-Id`, query parameters, or request-body `user_id` as proof of identity.
- User-owned queries include an owner predicate (`user_id = %s`) or join through the owner (`submissions` / `roadmap_versions`). Missing and not-owned submission IDs return the same `None` result.
- Denied cross-user access is recorded in `audit_logs` with action `CROSS_USER_ACCESS`, outcome `DENIED`, and a generic reason. Submission contents are never written to audit logs.
- The caller owns transaction boundaries for `data_access.py`; commit successful business operations and roll back failed ones.

## File storage

- Only TXT, CSV and SQL text files encoded as valid UTF-8 are accepted. Empty files, NUL bytes, invalid UTF-8 and files over `MAX_FILE_SIZE_MB` are rejected.
- Default file-size limit is 5 MB. Set `MAX_FILE_SIZE_MB` in the local `.env` to change it; do not commit `.env` secrets.
- Stored names are generated by the service. File reads must first authorize the owning submission through `read_owned_submission_file`; do not expose raw paths or call `read_stored_file` directly from an HTTP endpoint.
- Physical storage is under `secure_storage/`, outside any public/static web directory. Deletion of a missing file is treated as already deleted; other failures return `False`.

## PII and LLM boundary

- `redact_pii(text, known_name=...)` masks email, phone and the exact known name supplied from the authenticated user's own profile. It is not generic name/entity recognition and cannot guarantee removal of every identifying detail.
- Call `redact_pii` before forwarding user submissions to an LLM. Do not send raw submissions, access tokens, passwords, or secrets to the model provider.
- `verify_evidence_quote` checks whether an evidence quote appears in the submitted text; it does not by itself prove the claim is true.

## Retention, backup and audit

- Current database file retention default is 90 days (`submission_files.expires_at`) and cleanup is handled by the retention job/migration.
- Backup retention of at most 30 days is a **proposal pending team confirmation**, not an approved policy.
- Audit logs should not contain submission text or raw PII. The schema protects audit rows from deletion/editing except the actor foreign key being nulled on account deletion.
